# 角色动画 · 碰撞 · 特效 · 音效 —— 操作与接口说明

> 对应提交：本轮修 T-pose/悬空、接入 shouji 特效、补齐音效槽位

---

## 一 · 必须按顺序执行的三步

Unity 里依次点这三个菜单，**顺序不能反**：

```
① BugParty2D ▸ 接入 SCP 角色（完整：模型+动画+纹理）
② BugParty2D ▸ Build Room Scene
③ BugParty2D ▸ 接入肘击特效（art/shouji）
```

- ① 会重新导入 8 个 fbx 并生成重绑定动画，需要一两分钟
- ② 必须在 ① 之后 —— 建场时才会读到新的角色 Prefab
- ③ 必须在 ② 之后 —— 它要往场景里的玩家身上填槽位

③ 执行完记得 **Ctrl+S** 保存场景。

## 二 · T-pose 的根因与解法

### 为什么上一版没修好

上一版走 Humanoid 方案，指望 Unity 的自动骨骼映射绕过路径名不匹配。
实测**彻底失败**：重新导入后 fbx 的 `humanDescription` 里

```
human 映射条数: 0
skeleton 条数:  0
```

生成的 Avatar 是**空壳**。Animator 拿到空 Avatar 只能播 root motion，
骨骼曲线全被忽略 → 角色停在导入姿态。

原因是熊/猫是拟人角色，骨骼比例不符合人体，Unity 认不出标准人体槽位。

### 现在的解法：Generic + 曲线路径重写

```
模型骨骼    Polydactyl_Metarig / hips / spine / chest …
动画骨骼    PolyAnim / root / ORG-hips / ORG-spine …
            └─ 去掉 ORG- 前缀后，78 根骨骼 100% 同名
```

`SCPAnimRebind` 逐条读原 clip 的 `EditorCurveBinding`，剥掉 `ORG-` 前缀后
查表替换 `path`，写成独立 `.anim` 到 `Art/Characters/Clips/`。

**原 fbx 不做任何改动**，结果完全可预测。

排除的骨骼类型（映射过去会与真实骨骼打架）：

| 前缀/后缀 | 含义 | 为何排除 |
|---|---|---|
| `MCH-` | Rigify 机械控制骨（263 根） | IK 目标、拉伸修正，不驱动网格 |
| `VIS-` | 视口辅助显示骨 | 只在 Blender 里可见 |
| `.fk` / `.ik` | FK/IK 切换镜像骨 | 与主骨重复 |
| `_hose` `_target` `_roll` | 辅助节点 | 同上 |

## 三 · 悬空的根因与解法

### 三种测量方式的对比

| 方式 | Bear 实测值 | 能用吗 |
|---|---|---|
| `SkinnedMeshRenderer.bounds.min.y` | **-0.0074** | ❌ 模型根带 scale=100 补偿，静态 AABB 完全失真 |
| 脚骨 `foot.L` 位置 | 0.8398 | ❌ Rigify 骨骼带旋转，`toe`(1.0153) 竟比 `foot` 高 |
| **BakeMesh 顶点最低 y** | 真实脚底 | ✅ |

现在 `AlignFeetToOrigin` 用 `SkinnedMeshRenderer.BakeMesh` 取 T-pose 下的
实际顶点，变换到 root 局部空间求最低 y，整体上移使其落到 0。

`ComputeScale` 用同一套逻辑取 `maxY - minY` 当身高 —— 两处算法必须一致，
否则对齐好了又被缩放搞错。

### 配套改动

`ArtSlot.characters[i].fitToSize = false`。
`fitToSize=true` 时 `ArtResolver.AlignToBounds` 会**用包围盒重新定位**，
把 Prefab 里做好的接地对齐覆盖掉 —— 那是原先悬空的直接成因。

## 四 · 碰撞体

### 现状盘点（场景实测）

| 类型 | 数量 | 说明 |
|---|---|---|
| `CharacterController` | 4 | 玩家移动与环境碰撞 |
| `BoxCollider` | 268 | 地板 221 + 家具/平台 47 |
| `CapsuleCollider` | **4（本轮新增）** | 玩家身体，防互相穿透 |

### 本轮加了什么

**玩家身体碰撞体**（`CapsuleCollider`，高 1.45 / 半径 0.34 / 中心 y=0.73）。

原因：`CharacterController` 只处理「自己撞环境」，
**两个 CC 之间是互相穿透的** —— 这是 Unity 的既有行为，CC 不是刚体，
不参与 CC-vs-CC 解算。结果四个人可以完全重叠站在同一格上，抢柜子时
看不出谁挤到了谁。

加 `CapsuleCollider` 后，CC 的 `Move()` 会把它当障碍物推开，角色之间有实体感。

尺寸刻意**比 CC 略小**（0.34 vs CC 的 0.38），避免两者边界打架导致贴身抖动。

### 家具碰撞的架构

家具用的是「父节点带 BoxCollider + 美术模型作为无碰撞子物体」：

```
Box_投影仪箱          [BoxCollider]  ← 碰撞在这里
├── ArtPivot          美术模型，Collider 已被 ArtResolver.StripColliders 清除
└── InteractPoint     交互判定点
```

这样换美术模型不影响碰撞尺寸。**已验证 47 个家具/平台全部有 BoxCollider。**

唯一没有碰撞的是 `FloatChair_*`（10 个悬浮装饰）—— 这是**刻意的**：
它们在 y=1.4~2.6 悬空且被 `BugAmbience` 持续旋转飘动，
加碰撞会把玩家顶飞或卡住。

## 五 · 肘击特效

### 为什么不能直接拖 shouji.prefab

那份 prefab 的 4 个 `ParticleSystem` 全是：

```
looping     = 1     ← 打一拳后特效永远不停
playOnAwake = 1
lengthInSec = 5     ← 实际粒子生命只有 0.15~5 秒，大量空转
scalingMode = Local ← 会随父级缩放
```

直接用会有三个问题：特效不停、被 `lifetime` 强杀时像被"剪断"、
被角色的 0.2 倍缩放压到看不见。

### 工具生成的两份副本

```
Assets/BugParty2D/Art/Vfx/
├── Vfx_ElbowHit.prefab     命中用，完整 4 层粒子
└── Vfx_ElbowSwing.prefab   挥空用，只留生命 ≤0.4s 的层（更轻）
```

三处调整（**原 prefab 完全不动**）：

| 改动 | 原因 |
|---|---|
| `main.loop = false` | 一次性播放 |
| `simulationSpace = World` | 打击特效应留在原地炸开，不被发射器拖着走 |
| `scalingMode = Shape` | 只有发射形状受 scale 影响，粒子自身大小不变 |
| 挂 `VfxAutoKill` | 按粒子实际存活判断销毁，不是固定时长 |

`VfxAutoKill` 用 `unscaledTime` 计时 —— 命中定格会把 `timeScale` 压到 0.12，
用 `Time.time` 的话定格期间存活判断也会变慢，看起来像特效卡住。

### 四个可挂时机

选中任意玩家，Inspector 的 `ElbowVfxHook`：

| 槽位 | 时机 | 行为 |
|---|---|---|
| `windupVfx` | 蓄力（0.12 秒） | 挂手部跟随，挥出时自动销毁 |
| `swingVfx` | 挥出（**挥空也播**） | 朝角色正面 |
| `hitVfx` | 命中 | **自动朝向「攻击者→受击者」** |
| `getHitVfx` | 被击中 | 挂自己身上，跟着被击退动 |

工具会自动填 `hitVfx` 和 `swingVfx`，另两个留空给你自己配。

**四个玩家各有一份** —— 可以给红方配红色拳风、蓝方配蓝色。

## 六 · 音效填充栏（你要的四类）

全部在场景的 `AudioVfx` 对象上（建场自动创建）。**槽位留空就是不播，不报错。**

### ── 肘击 ──

| 槽位 | 时机 |
|---|---|
| `sfxElbowWindup` | 起手蓄力（比挥出早 0.12 秒） |
| `sfxElbowSwing` | 挥出，**不论是否命中** |
| `sfxElbowHit` | 命中，与 swing 叠加 |
| `sfxItemKnockedOut` | 打掉对方道具 |

### ── 搜索 ──

| 槽位 | 时机 |
|---|---|
| `sfxSearchStart` | 开始翻找 |
| `sfxSearchLoop` | **循环翻找音（本轮新增）** |
| `sfxSearchInterrupt` | 被打断 |
| `sfxSearchComplete` | 读条走满，**空柜子也播** |
| `sfxItemCollected` | 拿到道具 |
| `sfxItemRare` | 稀有道具优先 |

`sfxSearchLoop` **按玩家分别管理**：4 个人同时搜不同柜子时各有一个
`AudioSource` 挂在自己身上，不会互相掐断。

### ── 脚步与跳跃 ──

| 槽位 | 说明 |
|---|---|
| `sfxFootsteps[]` | **脚步声（本轮新增）**，可放多个随机取 |
| `sfxFootstepsPlatform[]` | 在桌子/矮柜上的脚步，留空则统一用上面那组 |
| `footstepVolume` | 0.45 |
| `footstepPitchJitter` | 0.12，避免连续踩踏像复读机 |
| `sfxJump` / `sfxLand` / `sfxLandHeavy` | 跳跃与落地 |

**脚步是按移动距离触发，不是按时间。** 固定时间间隔在两种情况下明显不对：

- 玩家贴着墙推 → 原地不动却一直在响
- 被击退滑行 → 没有走的动作却在响

按累计水平位移触发（`FootstepEmitter.strideLength` 默认 0.62 米），
走多远响多少步，而且走快走慢的步频会自动不同。

四种状态不响：**离地 / 被击退硬直 / 正在搜索 / 已出局**。

### ── 背景音乐 ──

| 槽位 | 阶段 |
|---|---|
| `bgmIntro` | 开场介绍 |
| `bgmSearching` | 搜索阶段（**玩家听最久，最重要**） |
| `bgmCollapse` | 终局塌陷 |
| `bgmSettlement` | 结算穿越 |

随 `OnPhaseChanged` 自动切换，带交叉淡化（`musicFadeTime` 默认 0.8 秒）。

- 用独立 `AudioSource`，与音效分开才能各自调音量
- 淡化用 `unscaledDeltaTime` —— 命中定格不该让音乐淡化变慢
- `musicEndPitchUp` 只在搜索最后 35% 生效，集中末段才有压迫感

另有 `alarmLoop`（警报循环音，随倒计时升高音调与音量）。

## 七 · 排查表

| 现象 | 原因 | 处置 |
|---|---|---|
| 还是 T-pose | ① 没执行，或重绑定生成 0 个 | 看 Console 的 `[Rebind]` 行，`生成 N 个` 应 ≥ 20 |
| 角色仍悬空 | 建场没重跑 | 必须在 ① 之后执行 ② |
| 角色陷进地板 | 缩放算错 | 调 `characters[i].yOffset` 微调 |
| 角色太大/太小 | — | `RoomArtConfig.characterHeight`（默认 1.5） |
| 角色背对镜头 | — | `characters[i].yawOffset` |
| 特效不出现 | 槽位空 / 没重建场景 | 执行 ③，检查玩家的 `ElbowVfxHook` |
| 特效太大/太小 | — | `ElbowVfxHook.scaleMul` |
| 特效朝向乱 | — | 关掉 `hitFaceAttackDir` 试试 |
| 特效永远不消失 | 原 prefab 被直接拖进槽位了 | 换成 `Art/Vfx/Vfx_ElbowHit` |
| 脚步声不响 | `sfxFootsteps` 空 | 拖音频进去；或看玩家有没有 `FootstepEmitter` |
| 脚步太密/太稀 | — | `FootstepEmitter.strideLength`（0.62） |
| 玩家还能重叠 | 建场没重跑 | `CapsuleCollider` 是建场时加的 |

## 八 · 视觉过载提醒

现在肘击命中时会同时触发**四层**反馈：

```
冲击环（ImpactRing）  20 片方片水平铺开
命中定格（HitStop）    timeScale 0.12 × 0.055 秒
屏幕抖动               0.16 起，按命中人数递增
shouji 粒子特效        本轮新增
```

接进来后可能太满。建议先看效果，觉得过载就把冲击环关掉：

```
选中玩家 ▸ PlayerActionFx ▸ Spawn Impact Ring  取消勾选
```

**命中定格建议保留** —— 那是打击感的核心，成本极低。
`ElbowAbility.hitStopDuration` 0.04~0.07 比较自然，超过 0.1 会明显卡顿。
