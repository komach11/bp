# 场景衔接操作指引（密室搜刮 → 海岛捕鱼）

> 代码已全部就绪，推送至内网 `meetingroom` 分支提交 `dbf6ef6`。
> 本文档只讲**你要在 Unity 里做什么**。

---

## 一、先搞清楚在哪个工程操作

**衔接测试只能在内网工程做，本地工程做不到。**

| | 本地 `C:\AAA000\密室` | 内网 `minigame` |
|---|---|---|
| 密室场景 | ✅ | ✅ |
| 捕鱼场景 `GameScene_PartyFishing` | ❌ 没有 | ✅ |
| PartyGame 代码（道具、玩家、大厅） | ❌ 没有 | ✅ |
| Netcode 包 | ❌ 没装 | ✅ |
| 渲染管线 | Built-in | URP 14.0.12 |

本地工程只能测密室本身（搜刮、塌陷、结算界面），**跳场景那一步跳不过去**——目标场景不存在。

所以下面的步骤分两部分：**A 在本地验证密室**（可选），**B 在内网验证完整链路**（必做）。

---

## 二、A · 本地验证密室（可选，约 5 分钟）

只是想确认结算界面能正常显示、道具只掉 4 种，可以在本地做。

### A1. 重新建场

菜单 `BugParty2D ▸ Build Room Scene`（或 `Tools ▸ BugParty2D ▸ Build Room Scene`）。

> ⚠️ 你 12:13 建的 `Assets/0.unity` 已经是新版（含吊扇与美术通道），但它**没入库**，
> 而且文件名是 `0.unity` 放在 `Assets/` 根下，建议改名并移到 `Assets/Scenes/`。

### A2. RoomManager 配置

选中 Hierarchy 里 `=== Room2D === ▸ RoomManager`：

| 字段 | 设为 | 说明 |
|---|---|---|
| `Next Scene Name` | **留空** | 本地没有捕鱼场景，填了会报「场景不存在」 |
| `Loop For Testing` | ✅ 勾上 | 结算后自动重开，方便反复看 |
| `Settlement Display Time` | `4` | 结算清单停留秒数 |
| `Verbose Log` | ✅ 勾上 | Console 会打印携带清单 |

### A3. 运行并观察

按 Play，等一局跑完（或用 HUD 的调试键跳过搜索阶段），应该看到：

```
        搜刮结束 · 携带清单
     这些道具将带入下一环节使用

  红方       大渔网　小刀
  蓝方(AI)   小渔网
  黄方(AI)   空手离场
  绿方(AI)   水雷　大渔网

      即将进入：（未配置）
```

**验证要点**：
- 道具名只应出现「大渔网 / 小渔网 / 小刀 / 水雷」四种
- 若出现「平底锅 / 辣椒 / 手铐」等，说明 `RoomConfig.restrictToCarryableItems` 没勾上
- Console 应有 `[Room2D] 携带进入下一关：slot0 [玩家] 红方 → 大渔网、小刀`

## 三、B · 内网验证完整链路（必做）

### B1. 拉取最新代码

```bash
cd <你的内网工程目录>
git pull origin meetingroom
```

如果你还没在本机 clone 过内网工程，先 clone：

```bash
git clone https://git.woa.com/yitianchen/minigame.git
cd minigame
git checkout meetingroom
```

> ⚠️ 这个仓库用了 Git LFS。如果本机没装 `git-lfs`，clone 后会出现大量「假删除」
> （字体、模型显示为已删除）。**这种情况下千万不要 `git add -A`**，会真的删掉它们。
> 建议先装 `git-lfs`：`git lfs install`。

### B2. 确认拉到的内容

```bash
# 这三个文件必须存在
ls Assets/Scripts/PartyGame/Net/CarryOverReceiver.cs
ls Assets/BugParty2D/Scripts/Core/CarryOverData.cs
grep -n "EquipLoadoutFor" Assets/Scripts/PartyGame/Net/PartyPlayerSpawner.cs
```

最后一条应输出 `146: if (mgr != null && pp != null) mgr.EquipLoadoutFor(pp, slot);`

### B3. 用 Unity 打开，等编译

内网 Unity 版本是 **2022.3.62f3c1**（注意 `c1` 后缀，是内网定制版）。

编译应该无错误。如果报错，把错误贴给我。

> Unity 会为 `CarryOverReceiver.cs` 自动生成 `.meta`，记得连它一起提交。

### B4. 在内网工程里建密室场景

菜单 `BugParty2D ▸ Build Room Scene`。

**注意：内网是 URP，密室的占位方块可能显示为洋红色。** 这是已知问题（`CreatePrimitive` 默认吃
Built-in 的 Standard shader），不影响衔接逻辑验证，但视觉上会很难看。要修的话告我。

建完后 `File ▸ Save As` 存成 `Assets/Scenes/GameScene_MeetingRoom.unity`。

### B5. 配置 RoomManager

选中 `=== Room2D === ▸ RoomManager`：

| 字段 | 设为 |
|---|---|
| `Next Scene Name` | **`GameScene_PartyFishing`** |
| `Loop For Testing` | ❌ **取消勾选** |
| `Settlement Display Time` | `4` |
| `Verbose Log` | ✅ 勾上 |

> `nextSceneName` 必须与场景文件名**完全一致**（不含 `.unity` 后缀，区分大小写）。
> 代码里已加保护：`loopForTesting` 与 `nextSceneName` 同时配置时以跳场景优先，
> 但配置理清楚更好。

### B6. Build Settings 加两个场景

`File ▸ Build Settings`，把这两个都拖进去并勾选 `enabled`：

```
✅ Assets/Scenes/GameScene_MeetingRoom.unity      ← 索引 0（第一个）
✅ Assets/Scenes/GameScene_PartyFishing.unity
```

**密室必须在前面**（索引 0），因为流程是密室 → 捕鱼。

> 场景不在 Build Settings 里，`SceneManager.LoadScene` 会直接失败报
> 「Scene couldn't be loaded because it has not been added to the build settings」。

### B7. 检查捕鱼的道具配置

选中捕鱼场景里的 `PartyGameManager`，看 `Config` 字段指向的 `PartyGameConfig` 资产。

确认它的 **`All Items`** 数组里这 4 种 `ItemDataSO` 都在：

| ItemKind | 对应密室道具 |
|---|---|
| `LargeNet` | 大渔网 `net_large` |
| `SmallNet` | 小渔网 `net_small` |
| `Knife` | 小刀 `knife` |
| `Mine` | 水雷 `mine` |

**如果某个 kind 不在 `allItems` 里，密室带过去的那件道具会被静默跳过**——
`LookupItem()` 返回 null，接收端 `continue`。

### B8. 跑一遍完整流程

1. 打开 `GameScene_MeetingRoom`，按 Play
2. 搜几个容器，拿到道具
3. 等塌陷结束 → 看结算清单（记下红方拿到了什么）
4. 4 秒后自动跳到捕鱼场景
5. **检查手里的道具是不是密室拿到的那两件**

**Console 应该看到这个序列**：

```
[Room2D] 携带进入下一关：
  slot0 [玩家] 红方 → 大渔网、小刀
  slot1 [AI] 蓝方 → 小渔网
[Room2D] 单机加载下一关：GameScene_PartyFishing
[CarryOverReceiver] slot=0 从密室带入 2 件道具
[CarryOverReceiver] slot=1 从密室带入 1 件道具
[PartyPlayerSpawner] Spawned PLAYER slot=0 for id=0 at ...
```

## 四、排查表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 结算后停在密室不跳转 | `nextSceneName` 为空 | 填 `GameScene_PartyFishing` |
| 报「Scene couldn't be loaded」 | 场景没进 Build Settings | 见 B6 |
| 跳过去了但手里是默认装备 | Console 有 `未找到密室 CarryOverData` → 密室代码没编译进同一程序集<br>或 `无法识别的道具类型` → ItemKind 名字不匹配 | 看 Console 具体哪条 |
| 跳过去了但手里空空 | `allItems` 里缺对应 `ItemDataSO` | 见 B7 |
| 结算清单里出现平底锅、手铐 | `restrictToCarryableItems` 没勾 | 选中 `RoomConfig2D` 勾上 |
| 结算清单一闪而过 | `settlementDisplayTime` 是 0 | 设为 4 |
| 联机时只有主机切了场景 | 正常，客户端等服务端广播 | 代码已处理，会走 `NetworkSceneManager` |
| 房间里全是洋红方块 | URP 下 `CreatePrimitive` 材质问题 | 已知，不影响逻辑，要修告我 |

## 五、还没做的部分

**密室联网化（原计划第 3 步）没做。** 当前状态：

- 密室是**单机**的，`CarryOverData` 是静态类
- 单机 / Host 模式下衔接完全正常
- **联机时，非主机的客户端拿不到密室结果**——因为静态类在每个客户端各有一份，
  各自的密室是本地跑的，结果不同步

如果只是本地单人测试或 Host 单机跑，现在就能用。真要 4 人联机，需要做联网化：

| 要改的 | 为什么 |
|---|---|
| `PlayerActor` → `NetworkBehaviour` | 移动要服务端权威或客户端预测 |
| `PlayerInventory` → `NetworkVariable` | 否则各端背包不一致 |
| `SearchContainer.remainingYield` 服务端权威 | 否则同一个柜子被搜出两份道具 |
| **`FloorTile` 塌陷由服务端决定并广播** | ★最关键。否则各端塌的格子不同，有人踩空有人没事 |
| 接入现有 `LanLobbyManager` | 不要另搞大厅，否则玩家要在两个大厅间来回 |

准备做的时候告诉我。

## 六、附：数据是怎么传的

```
密室 RoomManager.HandoffToNextLevel()
  ↓  按 slotIndex 存入
CarryOverData（静态类，跨场景不丢）
  slot0 → { isBot:false, color:Red,  itemIds:["net_large","knife"] }
  slot1 → { isBot:true,  color:Blue, itemIds:["net_small"] }
  ↓  切场景（Netcode 服务端走 NetworkSceneManager，否则 SceneManager）
捕鱼 PartyPlayerSpawner.SpawnFor(clientId, slot)
  ↓  Spawn 之后立刻
PartyGameManager.EquipLoadoutFor(pp, slot)
  ↓  有数据就走这条
CarryOverReceiver.TryEquipFromCarryOver(pp, slot, LookupItem)
  ↓  反射读 CarryOverData.GetNextLevelKinds(slot) → ["LargeNet","Knife"]
  ↓  LookupItem(kind) → ItemDataSO
pp.TryEquipItem(so)   槽位满则 ForceReplaceLastSlot
```

**为什么用 slotIndex 而不是 PlayerColor**：捕鱼的 `LanLobbyManager` 用 `slotIndex`
标识玩家，那是两个场景唯一对得上的键。密室的 `PlayerColor` 枚举 0~3 正好对应槽位 0~3。

**为什么用反射**：让捕鱼场景能脱离密室单独运行。没有密室代码时 `ResolveCarryType()`
返回 null，自动回退 `EquipDefaultLoadoutFor`，而不是编译失败。
